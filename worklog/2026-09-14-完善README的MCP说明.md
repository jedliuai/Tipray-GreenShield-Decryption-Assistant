# 完善 README 的 MCP 说明

## 1. 做了什么

重写并扩充了 README 中的 Agent / MCP 章节，在首页标语和徽章中加入 MCP 能力，并用完整场景解释 MCP 解决的问题、自动处理流程、四个工具的职责、普通 F8 与 MCP 的关系、安全边界和各种状态含义。同时加入 F8 + MCP 合体包的直接下载入口。

## 2. 为什么做

原 README 虽然已经列出了 MCP 工具和配置，但更像开发接口清单，没有直接回答普通用户最关心的“这个 MCP 到底有什么用”。新的说明从 Agent 打不开加密文件的真实场景出发，让人一眼看懂它如何减少手动切换和重复下指令。

## 3. 有什么值得记住的决策、坑或技术点

- 把 MCP 定位为 Agent 与本机授权解密能力之间的标准接口，而不是另一种破解方法或独立解密引擎。
- 明确普通 F8 和 MCP 共用同一个托盘服务，避免用户误以为需要同时运行两套后台程序。
- 用 `pending`、`unreadable`、`unverified` 和 `decrypted` 解释完成边界，强调申请已发送不等于解密完成。
- 在功能说明旁直接放合体包链接，减少用户在 Release 资产中辨认版本的成本。

## 4. 一句话亮点

这次 README 不只告诉你 MCP 有哪些按钮，而是讲清楚它如何让 Agent 遇到绿盾密文也能自己接上工作流。
