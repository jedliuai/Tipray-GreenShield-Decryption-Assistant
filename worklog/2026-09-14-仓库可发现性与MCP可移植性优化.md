# 仓库可发现性与 MCP 可移植性优化

## 做了什么

把项目从“代码仓库”重新整理成一个可以长期传播的公开产品：统一了中英文定位，重写 README 前半部分的理解与上手路径，补充安全说明、贡献指南、Issue 模板和引用信息；同时修掉公开 MCP 配置依赖本机绝对路径的问题，加入 Codex 一键接入脚本，并准备新的可移植合体包。GitHub 仓库名、About、Topics、Website 和 Release 也一起调整到同一套表达上。

## 为什么做

原来的核心能力其实很独特，但仓库名难以让英文搜索识别，“Auto Decryption”又容易被误解为绕过安全产品；README 先讲原理后讲下载，陌生用户不容易迅速判断自己是否适用。更严重的是插件模板写死了开发机路径，公开用户照着安装会直接失败。要让发现、理解、信任、使用和传播真正连起来，必须先解决这些真实摩擦。

## 值得记住的决策、坑或技术点

- 项目定位选择“授权解密申请助手”，把速度优势和保留官方审批链同时说清楚，不用夸张的破解叙事换取流量。
- README 前部只回答是什么、适合谁、为什么可信、怎样最快开始；实现细节留到后面。
- Codex 插件里的 MCP 改用相对路径，并把运行文件复制到插件自己的 `bin` 目录；普通安装则通过脚本动态注册用户电脑上的绝对路径。
- Windows PowerShell 5.1 会把 UTF-8 无 BOM 的中文脚本误读为本地代码页，因此双击安装脚本的运行期文本保持纯 ASCII。
- 原构建脚本即使编译失败仍可能返回成功，已经为每一步补上错误码检查，避免错误产物被发布。
- 没有擅自添加开源许可证，因为许可证类型属于需要作者明确决定的法律选择；这件事留作后续。

## 一句话亮点

把一次 F8 的效率工具，升级成了能被搜索发现、能让陌生人放心安装、也能让 AI Agent 自动续跑的公开产品。
