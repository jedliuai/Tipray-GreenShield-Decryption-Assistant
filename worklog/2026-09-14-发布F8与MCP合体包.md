# 发布 F8 与 MCP 合体包

## 1. 做了什么

在 GitHub 的 v1.4.0 Release 中额外发布了一个名称清晰的 `GreenShieldQuickApply-Combined-F8-MCP-v1.4.0.zip` 合体包，并附上独立 SHA-256 校验文件。压缩包同时包含普通 F8 托盘版、CLI、MCP 适配器、Codex 插件模板、构建脚本、源码和使用文档。Release 页面也补充了资产说明，明确推荐下载合体包，同时保留原 v1.4.0 安装包。

## 2. 为什么做

原安装包实际上已经带有 MCP，但文件名看不出来，用户在 Release 页面无法一眼判断“普通 F8 版”和“Agent MCP 版是否需要分别下载”。单独增加一个名称明确的合体资产，可以直接表达它既能让人按 F8，也能让 Agent 自动申请解密。

## 3. 有什么值得记住的决策、坑或技术点

- 没有覆盖或删除原安装包，而是在同一 v1.4.0 Release 中增加独立资产，保持已有下载链接稳定。
- 打包前确认所有程序和插件文件与 v1.4.0 标签完全一致，避免把工作区未提交内容混入安装包。
- 上传后从 GitHub Release 元数据再次核对文件名、标签、大小和服务端 SHA-256 摘要。
- PowerShell 把多行 Release Notes 直接作为参数时，会将以短横线开头的行误解析为命令选项；改用标准输入传给 `--notes-file -` 更稳。

## 4. 一句话亮点

一个合体包，两种入口：人选中文件按 F8，Agent 遇到密文自动接管并继续工作。
