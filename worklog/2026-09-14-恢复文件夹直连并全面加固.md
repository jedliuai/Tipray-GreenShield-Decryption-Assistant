# 恢复文件夹直连并全面加固

## 1. 做了什么

恢复了 F8 对文件夹的直接申请能力，现在文件、文件夹以及二者混合多选都能作为同一个批次交给绿盾官方申请程序。顺手完成了一轮代码审查并修复多项问题：批次发送前完整校验和去重、申请窗口按 `LdApproval` 进程精确识别、不再自动关闭未处理窗口、发送失败不再误报成功、F8 注册失败明确提示、CLI 提交模式禁止误选其他窗口残留目标、桌面公共项目和隐藏扩展名识别增强、等待计时溢出修复、日志并发写入保护，以及开机自启始终指向托盘版程序。

## 2. 为什么做

直连版上线时为了谨慎，错误地加了一条“遇到文件夹就拒绝”的限制，但绿盾本地菜单插件原本就支持文件夹路径，因此造成了功能回归。与此同时，直连流程速度很快，任何目标识别或窗口匹配上的小概率错误都会更快地变成错误申请，所以这次不能只删掉两行判断，还要把发送前后的安全边界一起补齐。

## 3. 值得记住的决策、坑或技术点

- 文件夹不需要递归展开，直接传文件夹路径才与绿盾原生右键菜单行为一致，也避免工具自行猜测过滤规则。
- 整个批次必须先完成存在性、重复项和 512 字节路径上限检查，再发送第一条信号，否则后面的路径失败会留下半个批次。
- 只按“新建申请”标题找窗口会误伤其他程序；现在同时要求窗口属于 `LdApproval` 进程。
- 自动关闭旧申请窗口可能丢失用户尚未发送的内容；现在改为明确阻止新操作并提醒用户先处理旧窗口。
- `--once` 会真正发送申请，因此不能从任意资源管理器窗口自动捞一个残留选区；自动化时必须传准确 HWND。
- CLI 进程里的 `Application.ExecutablePath` 指向 CLI 自己，不能直接拿来做托盘自启目标。
- 真实验证使用临时空文件夹，只打开官方“新建申请”窗口，不点击发送；退出码为 0，随后关闭窗口并清理临时目录。

## 4. 一句话亮点

F8 不但重新支持整文件夹直达绿盾申请，还把“快而可能误发”升级成了“快、准、批次完整且不碰旧申请”。
