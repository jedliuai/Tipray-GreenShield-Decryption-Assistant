# 完善仓库 About 与搜索发现

## 1. 做了什么

把 README 前段调整成“先快速定位、后详细解释”的结构：标题直接体现 F8 与 MCP，首段自然包含绿盾、天锐绿盾、Tipray、MCP Server 和 AI Agent 等中英文概念，新增双入口对照表、英文摘要和合体包入口；同时删除后文重复的普通版/MCP 对照，只保留 MCP 原理、工具、接入和安全边界。

还完善了 GitHub 仓库右侧 About 区域，填写一句话描述、Latest Release 链接和与项目高度相关的 Topics，让仓库在 GitHub 搜索、Topic 页面、API 和外部索引中拥有更完整的机器可读元数据。

## 2. 为什么做

原来的 MCP 详细说明在 README 较靠后，第一次打开仓库的人容易只看到 F8，以为这是单纯的快捷键工具；右侧 About 又完全为空，GitHub 和外部搜索系统缺少可用于理解、分类与展示项目的结构化信息。需要让人和机器都能在页面前部迅速识别“双入口、官方链路、Agent 自动续跑”这三个核心特点。

## 3. 有什么值得记住的决策、坑或技术点

- 前段只承担一句话定位和模式选择，后文承担工作机制和安全细节，避免同一段 MCP 介绍换句话重复两遍。
- 搜索优化使用自然语义和真实产品/技术名称，不堆砌无关热门词；Topics 也控制在项目真正覆盖的范围内。
- 中文描述负责命中绿盾、天锐绿盾等本地搜索，英文摘要和 Topics 负责 Tipray、MCP、DLP、AI Agent 等国际化或机器检索表达。
- About 的 Website 指向 Latest Release，比重复填写仓库首页更有行动价值。
- GitHub 官方建议 Topics 使用小写字母、数字和连字符，最多 20 个；配置时遵循这一限制。

## 4. 一句话亮点

让仓库首页同时对人和 AI 说清楚：这不只是一个 F8 工具，更是能让 Agent 遇到绿盾密文后自动续跑的本机 MCP 服务。
