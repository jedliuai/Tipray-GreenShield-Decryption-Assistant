# 精简直连版并发布 GitHub

## 1. 做了什么

把当前版本正式收敛为 F8 本地直连方案：删除了右键菜单枚举、Shift+F10、鼠标悬停、子菜单定位和旧版 `--apply-once` 命令，只保留文件选择识别、绿盾本地插件调用、官方申请窗口等待和发送按钮操作。项目外层残留的旧源码、旧可执行文件与旧构建脚本也一并删除，避免以后误启动。重新编译了托盘版与 CLI 版，并把 README 改造成包含流程图、功能对比、原理说明、使用指南、兼容性、安全边界、排错方法和搜索关键词的完整项目主页。

## 2. 为什么做

旧实现虽然能用，但本质上是在屏幕上模拟人点击，容易受 Windows 右键菜单、焦点、动画和固定等待影响。现在已经确认可以把文件路径直接交给绿盾官方本地菜单插件，就没有必要继续维护两套差异很大的流程。精简后代码更短、故障点更少，也能清楚解释速度为什么提升。

## 3. 值得记住的决策、坑或技术点

- 删除旧代码只发生在当前分支，没有重写 Git 历史；旧版仍保存在提交 `47d4f68` 中，随时可以查看或恢复。
- 直连的是本机官方组件和官方申请程序，不是服务端通信；审批链路仍然保留。
- 托盘启动时预热插件，F8 触发时跳过菜单组件冷启动；剩余主要耗时来自官方申请窗口本身。
- 透明读取再另存的路线在当前策略下行不通：受控扩展名一落盘就会被再次加密。
- 验证时只运行 `--probe-direct` 与 `--help`，没有为了测试而额外发送申请。
- README 的关键词要自然地出现在标题、简介、原理和关键词区，不能只堆在页面末尾。

## 4. 一句话亮点

把“右键、找菜单、展开、等待、发送”的绿盾解密申请，压缩成一次真正直达官方组件的 F8。
