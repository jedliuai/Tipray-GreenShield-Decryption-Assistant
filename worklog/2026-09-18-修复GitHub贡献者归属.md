# 修复 GitHub 贡献者归属

## 做了什么

把这台电脑的全局 Git 提交身份从旧账号 `liuxiaomang7` 改成了 `jedliuai`，邮箱使用 GitHub 提供的账号专属 noreply 地址。当前仓库已有的 19 个提交也统一改写了作者和提交者身份，所有版本标签随历史一起迁移，并把 README 中依赖旧 commit SHA 的链接改成稳定的版本标签链接。

## 为什么做

GitHub 判断贡献者时看的是 commit 内部记录的作者邮箱，而不是仓库属于谁、也不是谁执行了 push。之前全局 Git 配置一直使用 `liuxiaomang7 <948326884@qq.com>`，所以即便代码推送到了 `jedliuai` 的仓库，贡献仍会显示在旧账号名下。

## 值得记住的决策、坑或技术点

- 以后本机新提交统一使用 `jedliuai <254592765+jedliuai@users.noreply.github.com>`，既能正确关联 GitHub 账号，也不会公开私人邮箱。
- 只修改作者、提交者和标签签署者元数据，改写前后的文件树完全一致；提交说明和时间也保持不变。
- 历史改写会让 commit SHA 改变，因此 README 不再链接某个短 SHA，而改用稳定的 `v1.2.4` 标签。
- 远端同步需要强制更新主分支和旧标签。其他已经克隆过这个仓库的人需要重新克隆或将本地分支重新对齐。
- 改写前在仓库外保存了完整 bundle 备份，确认 GitHub 归属无误后也可以继续保留一段时间。

## 一句话亮点

仓库属于谁、代码由谁贡献，从此终于在 GitHub 上显示成同一个人。
